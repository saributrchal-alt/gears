# คลังเก็บของวัดพุทธอุทยานนาเทิง

เว็บไซต์ https://gears.nathoeng.com — ใช้สมาชิกของ https://watt.nathoeng.com

## เปิดใช้งาน (ครั้งแรก)

1. เปิด Supabase **โปรเจกต์เดียวกับเว็บวัดและห้องสมุด** → SQL Editor → New query → คัดลอก `schema.sql` ทั้งไฟล์ → Run ตาราง `gears_*` แยกจากห้องสมุด ไม่แก้ทะเบียนสมาชิกหรือหนังสือ
2. Vercel → โปรเจกต์ **gears** → Settings → Environment Variables เพิ่ม **Production**:
   - `SUPABASE_URL` คัดลอกจากค่าของโปรเจกต์เว็บวัด / library
   - `SUPABASE_SECRET_KEY` คัดลอกจากค่าของโปรเจกต์เว็บวัด / library
   ห้ามวางคีย์ในไฟล์เว็บ GitHub หรือแชต
3. Build settings: Framework Preset **Other**, ไม่ต้องตั้ง Build Command, Output Directory `.` (root); Vercel ตรวจ `api/gears.js` เป็น Node function
4. Redeploy gears หลังเพิ่ม Environment Variables
5. ฝั่งเว็บวัดต้อง deploy commit ที่เพิ่ม `gears-session`, `gears-verify` ใน `api/line-login.js` และลิงก์คลังในบัญชีของฉัน ใช้ `SESSION_SECRET` เดิมของเว็บวัด ไม่ต้องสร้าง secret ใหม่หรือคัดลอก SESSION_SECRET มาที่ gears
6. เข้าสู่ระบบสมาชิกที่เว็บวัดก่อน แล้วเปิด gears → สำหรับเจ้าหน้าที่ → เพิ่มข้อมูลอุปกรณ์ → รับอุปกรณ์เข้าคลัง

## ฟีเจอร์

- หน้าแรกโปร่ง ช่องค้นหา + หมวดหมู่ ผลลัพธ์แบ่งหน้า ไม่ใส่รายการสมมติในฐานจริง
- หมวดเริ่มต้น 8 หมวดและเพิ่มหมวดเองได้; เพิ่ม/แก้ชื่ออุปกรณ์ รูปจาก URL รายละเอียด หน่วยนับ ซ่อนจากหน้าค้นหา
- รับเข้า 1–100 ชิ้นต่อครั้ง ออกรหัส NTG และบันทึกตำแหน่งเก็บรายชิ้น
- เลือกหลายอุปกรณ์/จำนวนเป็นหนึ่งคำขอ ใช้ชื่อจากทะเบียนสมาชิกจริง
- รับและคืนที่วัดเท่านั้น ไม่รองรับจัดส่ง ไม่เก็บที่อยู่จัดส่ง
- รออนุมัติ → รอรับ → อยู่ระหว่างยืม → แจ้งนำมาคืน → เจ้าหน้าที่ตรวจรับคืน
- ยกเลิกได้ก่อนส่งมอบ; เจ้าหน้าที่ปฏิเสธคำขอได้; ทุกสถานะมีเวลาและหมายเหตุ
- แจ้งนำมาคืน **ยังไม่ปล่อยของกลับให้ยืม** จนเจ้าหน้าที่ตรวจรับครบทุกชิ้น แยกพร้อมใช้/พักซ่อมรายชิ้น
- พิมพ์ A4 ใบบันทึกรวมชื่อผู้ยืม โทร เลขรายการ รหัสอุปกรณ์ กำหนดคืน และช่องลงชื่อ 3 ฝ่าย
- สมาชิกเห็นรายการตัวเอง เจ้าหน้าที่ role `admin` ตามทะเบียนวัดเห็นรายการทั้งหมด
- แสดงเกินกำหนดตามเวลาไทย สมาชิกถูกระงับใช้ไม่ได้ และไม่อนุญาตบัญชีโหมดสวมสิทธิ์

## ความถูกต้องและสิทธิ์

ใช้โทเค็นอายุ 3 นาที audience `nathoeng-gears` เก็บในหน่วยความจำ browser; เซิร์ฟเวอร์ตรวจโทเค็นกับเว็บวัดและตรวจสมาชิกฐานจริงทุกครั้ง โทเค็นจากห้องสมุดใช้แทนกันไม่ได้ SQL functions เข้าถึงได้เฉพาะ service_role พร้อมตรวจบทบาทซ้ำ ใช้ transaction, row locks และ unique partial index กันของถูกยืมซ้ำ RLS ปิดการเข้าถึงข้อมูลโดยตรงจาก anon/authenticated

## ทดสอบ

`npm ci && npm test` ทดสอบ SQL จริงใน PostgreSQL WASM (PGlite) รวม rollback, สิทธิ์, กันยืมซ้ำ, ยกเลิก, ส่งมอบ, ตรวจคืนครบทุกชิ้นและพักซ่อม; API ทดสอบไม่ให้สมาชิกทำงานเจ้าหน้าที่

หลังตั้งค่าจริง ให้ทดสอบอุปกรณ์หนึ่งชนิดสองชิ้น: สมาชิกส่งคำขอ → เจ้าหน้าที่อนุมัติ → ส่งมอบ → สมาชิกแจ้งคืน → เจ้าหน้าที่ตรวจรับ → ตรวจยอดพร้อมให้ยืม ทดสอบบัญชีสมาชิกทั่วไปและผู้ดูแลด้วย ก่อนใช้งานจริง

## ขอบเขตรุ่นนี้

เน้นอุปกรณ์ยืม–คืน การเบิกวัสดุสิ้นเปลืองและการคืนบางส่วนยังไม่รวม หากคืนไม่ครบให้คงรายการไว้และใส่หมายเหตุเมื่อรับคืนครบ ระบบยังไม่มีแจ้งเตือน LINE อัตโนมัติ รูปอุปกรณ์ถ่ายด้วยกล้อง เลือกไฟล์ หรือใช้ลิงก์ HTTPS ได้

## รูปอุปกรณ์: กล้องและการบีบอัด

ปุ่มถ่ายรูปใช้กล้องหลังเป็นค่าเริ่มต้นเมื่อมี รองรับกล้องคอมพิวเตอร์ด้วย และมีตัวเลือกใช้กล้องของเครื่อง/เลือกไฟล์เมื่อเบราว์เซอร์เปิดกล้องไม่ได้ ปิดกล้องจะหยุดทุก video track ทันที

เลือกภาพ → แสดงตัวอย่าง → ย่อด้านยาวสูงสุด 1,280 px → เข้ารหัส JPEG โดยตั้งเป้าขนาด 300 KB และจำกัด 500 KB → กดบันทึกข้อมูลอุปกรณ์จึงอัปโหลด การเข้ารหัสใหม่ไม่เก็บ EXIF/GPS เดิม รองรับไฟล์ต้นฉบับไม่เกิน 30 MB รูป HEIC ขึ้นกับการรองรับของเบราว์เซอร์

API ตรวจสิทธิ์ admin และขนาด/ชนิดไฟล์ก่อนจัดเก็บ รูปเก็บใน Supabase Storage bucket `gears-photos` ซึ่งเซิร์ฟเวอร์สร้างให้อัตโนมัติครั้งแรก **ไม่ต้องรัน SQL เพิ่ม** เป็นรูปอุปกรณ์สำหรับหน้าค้นหาสาธารณะ ไม่มีการให้สิทธิ์อัปโหลดจากเบราว์เซอร์โดยตรง
